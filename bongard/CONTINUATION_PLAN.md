# Bongard Continuation Plan

This plan records the August 2026 audit of the current `bongard/` tree, local
ignored experiment artifacts, and the latest substantive work in commit
`11c590e8` (`save WIP on Bongard primitives`). It supersedes no scientific
report; it identifies the implementation order needed to make the established
typed semantic-cone direction trustworthy and runnable.

## Direction preserved

The repository has progressed through four useful layers:

1. controlled symbolic concept induction and abstraction emergence;
2. a symbolic Bongard-LOGO action-program adapter;
3. an unrestricted raw-panel predicate-library crack loop; and
4. typed `SEMANTIC-PURE` cones introduced after paired semantic/code proposals
   collapsed to accidental scalar proxies.

The fourth layer is the active frontier. The next result should not come from
prompting the unrestricted loop harder. It should come from typed factorization,
honest visual witnesses, executed nuisance transformations, conditional MDL,
and cold replay.

## Audit findings at the start of this continuation

The following findings were true at the start of this continuation and are
retained as historical motivation; the execution-status section below records
their current disposition. The checked-in tests described several desired
mechanisms that the live runner did not enforce at audit time:

- An empty proposer-declared gluing could discharge an arbitrary rich
  semantic term without binding or checking any diagram nodes.
- `complexity_hint` and gluing costs were proposer-controlled and could be
  negative, so a proposal could game model selection.
- The verifier ran a hard-coded transformation battery instead of the
  proposal's declared morphisms; unsupported declarations were not reported.
- `contrast_interventions` were parsed but never executed.
- Several registered legs overclaimed their behavior: tangency was relabeled
  contact, rotational symmetry was inferred from a reflection residual, and
  some curvature/containment/symmetry operations were placeholders.
- The semantic runner used a lexicographic selector rather than the documented
  `RiskVector` plus conditional `ComplexityBreakdown` path.
- The default semantic runner called a candidate solved with up to one support
  and two leave-one-out errors. Exact instance status requires zero full-panel
  errors and zero threshold-refit diagnostic errors. These diagnostics refit
  only the threshold after the proposer saw all panels; they are not a genuine
  representation-level holdout.
- Promotion copied a taint-clean workspace but did not cold-replay it or store
  enough provenance to do so later. The sole local ignored promoted typed cone
  no longer reproduces its recorded verdict under the current verifier.
- Honest witness paths were only compile-tested. Expected absence of a witness
  on a negative panel was counted as a predicate crash, preventing an
  end-to-end classifier such as `TriangleWitness -> confidence` from being
  admitted.
- The documented `python3 -m pytest bongard` command had no declared Bongard
  environment. In the available default interpreter, the geometry tests failed
  because `scikit-image` is missing.

These are admission-boundary defects, not evidence against the semantic-cone
approach. They define the immediate work.

Adversarial implementation review found three further variants while Phase A
was underway: an unknown rich word could hide beside one covered term; empty or
stopword-only semantic declarations were vacuous; and node IDs shared a string
namespace with leg dependencies, so a decorative absent witness could collide
with a load-bearing leg name. All three now have regression tests and fail
closed.

## Execution status

- Phase A is implemented and green: strict IR/gluing/declaration checks,
  separated node/leg dependency provenance, expected witness absence by node
  and side, declared morphism execution, quarantined placeholders, and exact
  defaults are exercised by adversarial and constructive end-to-end fixtures.
  Score language is also executable rather than decorative: a bounded,
  clause-bound parser preserves comparator mode, operand, negation, claim and
  metric identity; absolute/count/binary/witness predicates become the actual
  rule used by every verifier protocol, while only genuinely relative claims
  fit a threshold.
- Phase B is implemented and green: the live selector uses explicit measured
  risks plus harness-derived conditional complexity; unimplemented risks stay
  null; promotion requires a data-self-contained RunSpec and an exact replay
  in a fresh Python process under matching recorded code/runtime fingerprints.
  The RunSpec contains every candidate from every proposal round, its proposal
  round/index/count, cone and verification digests, expected verifier result and
  candidate evaluation, the selected ID, and a fingerprint of the complete
  runner module. The checkpoint candidate manifest and full promoted selection
  record are canonically cross-bound to that evidence. Replay
  re-verifies the full candidate set and recomputes the winner before it can
  certify the promoted cone. Panel, cone, registry/source, policy, dependency,
  candidate, selection, and expected-verdict drift are tested.
- Phase C is materially underway, not finished. The proposer-visible registry
  now has a data-driven contract laboratory: every current leg has a direct
  constructive/codomain check, every advertised machine-readable failure mode
  has an adversarial probe, and every declared invariance and equivariance is
  enumerated in a completeness-checked matrix. Circle/arc/line/polygon fits
  reject unsupported geometry. Continuous relative proxies are metric-specific
  and count contracts name only the entities they count; neither can establish
  unrelated categorical claims such as `filled`. Placeholder helpers remain
  quarantined. The former intersecting-circle reachability gap is now
  closed for the tested raster substrate: Hough proposals inside a merged
  component are Taubin-refined and admitted only after full angular support,
  radial-tail, distinctness, joint-coverage, and balance checks; the resulting
  pair feeds constructive intersection. Remaining work includes broader
  composition paths. A new 648-case raster-composition matrix covers angles
  0–85 degrees and widths 1/3/5/7 for line/arc/S-curve counts, acute-triangle
  and quadrilateral classification, circle fitting, T-junction parts/contact,
  four-way intersection, and three-ray radial reachability.
- Phase D's offline engineering gate is implemented and green. A paid
  unrestricted-only n=1 exploratory pilot completed on 5 August 2026; its
  three-arm campaign cold-replays and records primary 0/1 ordinary unsolved,
  shuffled 0/1 canonical verifier failure, and held-fixed no-share 0/1. The
  full externally committed default campaign remains pending. The
  preparer can freeze one write-once maximum corpus with its exact panel bundle,
  independent basic/abstract RNG streams, fixed interleave, deterministic
  balanced shuffled-side assignments, and ordered 1/5/25 prefixes. The default
  preregistration contains 27 track-separated arms and
  artifact-certified complete-collection validation. Unrestricted predicate
  execution now uses the positive `bongard-predicate-purity/v2` capability
  manifest and restricted builtins; its selector uses
  `bongard-predicate-pricing/v3`, per-use rule structure charges, a conditional
  paid-definition ledger, and bounded exhaustive `risk-then-cost/v2` selection.
  Each production unrestricted attempt uses the pinned non-interactive Codex
  CLI. Its receipt binds the exact task, input/output source and log chain, raw
  and semantic panel identities, structured output, unique thread/event
  identity, explicit model/reasoning request, positive usage, output schema,
  CLI, and launcher. Because Codex JSONL can omit its model field, the
  receipt records that absence instead of asserting that the requested model
  was observed. The semantic
  Anthropic Messages path separately rejects any missing or substituted
  concrete response model. The unrestricted no-share result is derived by held-fixed
  repricing of the primary sources/rules/risks/outcomes; it is accounting-only,
  not a second adaptive solve-rate arm. Semantic and unrestricted resume,
  control, corpus-bundle, report, and promotion provenance are cross-bound.
  Historical ignored artifacts are not upgraded by these changes. The pilot's
  preregistration was local rather than externally timestamped, contains no
  semantic-pure arm, and has n=1 only, so a full externally committed
  execution is still required for confirmatory evidence.

## Phase A — truthful semantic gate

1. Validate the semantic IR before compilation:
   - reject negative or non-harness complexity;
   - reject unsupported call parameters instead of silently ignoring them;
   - require explicit semantic terms and valid morphism declarations;
   - require non-degenerate, typed, load-bearing gluings.
2. Make witness absence a typed, expected execution outcome. It must propagate
   to a negative decision without being confused with an implementation crash.
   Its machine-readable failure mode must be declared by the leg, and every
   executed result must satisfy the registered runtime codomain.
3. Execute declared preservation morphisms, report unsupported morphisms, and
   keep any dataset-wide stress battery as a separately named diagnostic.
4. Quarantine contracts whose implementations do not establish the witness
   named by the leg.
5. Make exact support and exact cross-validation the headline admission
   default. Any tolerance must produce an explicitly approximate status.

Gate: adversarial tests must fail every known semantic/complexity/gluing bypass,
and an honest typed shape witness must solve a synthetic positive/negative
problem end to end.

## Phase B — one authoritative selector and replay

1. Construct a `CandidateEvaluation` for every compiled cone. Populate every
   measured risk dimension and mark unimplemented dimensions as unmeasured,
   never silently zero-risk.
2. Fix Pareto dominance so inadmissible candidates cannot dominate admissible
   ones and every measured coordinate in the explicit selection tuple
   participates; unimplemented `null` coordinates remain outside ranking.
3. Select admissible candidates by conditional free energy
   `R + lambda * C(M | L)`, with a full complexity breakdown derived by the
   harness rather than the proposer.
4. Store a complete run specification: dataset/source/seed, panel hashes,
   every candidate cone and evaluation, selected candidate ID, verifier policy,
   registry versions and digests, predicate/threshold mode, and code state.
5. Cold-replay every candidate against the recorded panels, recompute
   conditional-MDL selection, and require that the reproduced winner is the
   promoted cone. Refuse promotion on any verdict, selection, or digest
   mismatch.

Gate: a promoted fixture must replay in a fresh process, while a changed panel,
cone, losing candidate, selector, registry, or verifier policy must be
detected.

## Phase C — primitive contract laboratory

1. Generate adversarial positives and negatives for every registered witness
   leg.
2. Test each claimed translation/rotation/reflection/scale contract directly,
   including off-grid rotations and stroke-width perturbations where the
   renderer makes them meaningful.
3. Prioritize the primitive work already indicated by the latest WIP:
   arc-length-resampled curvature, robust circle/arc fits, curvature-minima
   part decomposition, genuine tangency/containment, and axis-independent
   reflection/rotation symmetry.
4. Register a leg only after its witness and failure behavior pass the contract
   battery. Placeholder helpers may remain internal but must not carry semantic
   vocabulary in the proposer-visible registry.

Current checkpoint: `test_semantic_leg_contracts.py` covers all 57 currently
registered legs, all 36 advertised failure modes, all 57 scalar-invariance
declarations, and all 47 witness-equivariance declarations. It distinguishes
invariant measurements from coordinate-bearing witnesses that should transform
equivariantly. It also covers 648 off-grid/stroke-width composition
configurations across the load-bearing curve, polygon, circle, junction,
intersection, and radial chains. Internal
compatibility or placeholder helpers—including
`bbox_fill`, `closure_ratio`, `estimate_tangents`, containment/symmetry
placeholders, and the polygon-alias line decomposer—are not proposer-visible.

Gate: every proposer-visible leg has a tested constructive/codomain case, every
advertised failure mode has an adversarial probe, and every declared
invariance/equivariance is covered. The matrix is now present, but extending
the composition perturbation grid to the remaining paths keeps Phase C open.

## Phase D — re-establish evidence, then scale

The offline implementation work is complete:

1. `prepare_phase_d.py` samples once at the declared maximum, embeds the exact
   panels, and writes corpus/control/preregistration artifacts without creating
   a proposer or making an API call. With both sources selected, each source
   has its own deterministic RNG stream before the fixed interleave.
2. Scale means the nested ordered prefixes 1, 5, and 25 of that same frozen
   maximum. Runner limits must stay fixed at the maximum; changing the sampler
   limit creates a different corpus and is rejected by provenance checks. For a
   primary or shuffled proposer family, n1 is the only legal fresh start; n5
   requires a complete replay-valid n1 checkpoint in the same family artifact,
   and n25 requires n5. Same-scale resume is allowed, while a fresh higher-scale
   start, shrink, skipped predecessor, or incomplete predecessor fails before
   proposer construction and before any write. No-share scales are independent
   derived artifacts rather than a resumable family.
3. Each track has primary and three balanced shuffled-side replicates at every
   scale. Only `UNRESTRICTED` has no-share. Thus the default table has
   `3 * (2 * (1 + 3) + 1) = 27` arms, all reported separately. The complete
   collection validator requires all 27 and checks cross-scale prefix nesting.
4. Unrestricted predicate source is first admitted by the complete versioned
   `bongard-predicate-purity/v2` manifest: only its exact imports, restricted
   builtins, calls/values, methods/attributes, keywords, owned-scratch mutation,
   and resource forms are capabilities. A listed module root grants no other
   API.
5. Unrestricted pricing follows the exact AST dependency closure from each
   selected predicate through helpers, constants, and imports. Definitions use
   content identities and LOC-plus-literal costs; a rule separately pays call
   and binding structure on every use. Selection is exhaustive within the
   declared bound (constants and up to two of the 24 candidate atoms), ordered
   by empirical risk and then conditional cost. This resolves the flat-atom
   R4 incentive without pretending that raw LOC belongs on the same scale as
   risk. Panel-identity lookup is instructed against and its payload remains
   charged/visible, but rotated LOO over panels already shown to the proposer
   cannot categorically detect it; unseen-instance evidence is required for a
   generalization claim.
6. The shared ledger discounts only definition identities reached by earlier
   accepted rules. Unused or merely proposed code is not free. No-share copies
   the primary accepted source/rule/risk/outcome trace and repays its full
   definition closure per accepted use. It is an accounting ablation only;
   there is no independent no-share solve-rate claim. Semantic-pure no-share is
   excluded until learned semantic legs can be separated from the base
   registry.
7. Both tracks bind report records and resume state to corpus, embedded bundle,
   condition/control, track, sharing policy, and ordered prefix. Promotion
   refuses mismatched evidence. Semantic artifacts cold-replay the full
   candidate set and selector in a fresh process. Unrestricted artifacts
   sequentially replay each exact attempted source against embedded panels,
   recheck rule/fold/risk/receipt evidence under the recorded verifier/runtime
   fingerprint, and require the final library to equal the last accepted
   source. The offline collector independently cold-replays each originating
   artifact and embeds one digest-bound certification per arm.

The remaining sequence is the full externally committed empirical campaign;
the completed unrestricted-only n=1 pilot does not discharge it:

1. Prepare the maximum corpus once with
   `PYTHONHASHSEED=0 crack_lab/prepare_phase_d.py --source both --limit-per-source 25
   --scales 1,5,25`.
   This also freezes exact proposer parameters, the complete
   `bongard-predicate-purity/v2` manifest,
   `bongard-predicate-pricing/v3`, selector/verifier source hashes, Python, and
   dependency versions; any drift requires a new campaign.
   Publish or externally commit the preregistration digest before the first
   proposer call; local write-once paths alone do not prove temporal priority.
2. Before proposer construction, bind each run to
   `phase_d_preregistration.json`, its exact arm ID, and its generated
   execution tag. Use the canonical semantic output directory named by that
   tag. n1 is the only legal fresh start; resume the same
   track/condition/replicate family at n=5 and then n=25, publishing the
   distinct scale arm at each complete checkpoint. The runner rejects a fresh
   higher-scale start, shrink, skipped or incomplete predecessor before any
   proposer or write. Semantic uses fixed
   `--limit 25` with `--corpus-size`; unrestricted uses fixed `--limit=25`
   with `--max-problems=`.
3. Run every shuffled replicate through the full adaptive pipeline. Once each
   unrestricted primary trace exists, derive its matching held-fixed no-share
   artifact with `bongard_legs.py
   --no-share-from=<primary-execution-tag>`. Use the preregistered
   scale-specific target tags for n1, n5, and n25, passing the corresponding
   `--max-problems=` and no-share arm ID.
4. Under the same fixed `PYTHONHASHSEED`, run
   `crack_lab/collect_phase_d.py` over the explicit execution-artifact report
   directories. Accept the study only after it validates the full arm set,
   cold-replays each originating artifact, embeds every per-arm certification,
   and atomically publishes the write-once canonical campaign.
5. Only after that evidence exists should PowerPlay ordering or the classic
   Bongard set be resumed.

The completion criterion is not a larger nominal solve count. It is a corpus
result whose semantic claims factor through honest typed witnesses, whose
selection is conditional-MDL auditable, whose controls behave as preregistered,
and whose promoted artifacts cold-replay exactly.
