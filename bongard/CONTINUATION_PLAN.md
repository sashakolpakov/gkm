# Bongard no-launch continuation plan

The 2026-08-10 skeleton-graph calibration campaign is terminal. Its canonical
outcome is the custody GAP
`sha256:9e53320d9aebd0d07dc61e60f8709c445db66936462fa9997613b645ecfba2ef`.
This plan describes evidence required for an independently clean successor;
it does not authorize a live run.

## Current prohibitions

Do not:

- resume, amend, or reinterpret the terminal campaign;
- reuse its campaign intent filename, output root, exposure predecessor, or
  write-once stores;
- use the current HD action-program authority to claim program-blind
  calibration, target inference, DEV evaluation, or TEST evaluation;
- inspect official programs, labels, or target identifiers to choose a
  replacement cohort;
- convert the custody GAP into a semantic empty-version-space result;
- infer zero survivors from its `null` version-space fields; or
- launch any historical or retired command as a smoke test.

The incident opened no panel pixels or labels, but it conservatively exposed
all 4,400 HD programs before prediction. Pixel sealing and program sealing are
separate facts; the former does not repair the latter.

## Re-entry gate 1: independent clean authority

A successor begins only after a new metadata authority proves all of the
following without consulting exposed official program or label content:

1. A new campaign identifier and source lineage are frozen.
2. The population and every cohort member come from a program authority that
   was not exposed by the incident. The current ShapeBongard HD program file
   cannot establish that property.
3. Selection is performed from precommitted metadata by an actor/process that
   has not received target programs, labels, query roles, or held-out indices.
4. Cross-split and semantic-disclosure closure is computed before selection.
5. The cohort is not a reroll or substitute for a consumed, rejected, or
   terminal cohort.
6. All image, program, label, and model exposures are accounted separately.

If these facts cannot be proved, the correct outcome remains no launch. Safe
work may continue on synthetic fixtures, checked-in canonical metadata, and
already exposed engineering evidence, but it cannot create a benchmark
claim.

## Re-entry gate 2: new preregistration and stores

Before any pixel callback exists, freeze:

- the exact observer and dependency source hashes;
- passed-fit algorithm and record digests;
- calibration population, task/panel identity digests, alpha, task-level
  score, order statistic, and typed projection;
- model, feature, probability, artifact-size, and occurrence caps;
- a new exposure predecessor and exactly one allowed successor event;
- new output-root identity and exclusive claim protocol;
- prediction-before-label, formula-before-query, and prediction-before-label-
  reveal barriers; and
- every terminal GAP schema and recovery disposition.

Persist the intent, exposure child, and output-root claim with write-once
semantics. Freshly read and verify them from a separate process before issuing
any pixel capability. Serialized receipts alone are never capabilities.

## Re-entry gate 3: calibration-only execution

The first live stage, if separately authorized, is calibration only:

1. Read only the preregistered calibration panels.
2. Deduplicate exact PNG bytes and emit role-free raw inference rows.
3. Write, fsync, reload, and canonically reverify the complete raw batch.
4. Independently recompute features and probabilities and bind a receipt.
5. Only then construct the delayed-label reader.
6. Freeze whole-task conformal scores and population grants.
7. Cold replay from archived probabilities and delayed labels with zero pixel
   and model calls.

Missing, malformed, interrupted, inefficient, or out-of-population evidence
produces a typed calibration/population GAP. It never opens target, support,
query, or official TEST pixels.

Passing calibration is necessary, not sufficient. A target needs a separate,
external exact population-membership grant and a separate release authority.
Confidence cannot infer population membership from pixels.

## Re-entry gate 4: support version space

Only after all earlier authorities pass may a new support-only stage:

1. Produce complete candidate-independent typed observations.
2. Construct the entire frozen singleton/pair candidate inventory.
3. Evaluate every candidate deterministically on every support.
4. Persist the complete support matrix and its source/algorithm identities.
5. If no candidate survives, emit a typed semantic language/witness/search
   GAP with an exact zero count and matrix digest.
6. If survivors exist, let Codex rank only those verified candidates.
7. Freeze one Python predicate and cold-read it before any query release.

This is where a semantic GAP can arise. The current custody GAP stopped before
step 1 and provides no evidence about this version space.

## Re-entry gate 5: query and replay

Query access remains a distinct capability. It may be issued only after the
frozen predicate and complete support proof are durably verified. The runner
must then:

- authenticate each query PNG against its clean release authority;
- evaluate the already frozen predicate without proposal or threshold change;
- persist all predictions before label reveal;
- reveal only the authorized query labels;
- produce fixed-denominator accounting including abstentions and errors; and
- cold replay the entire decision with zero model calls.

There is no negation, polarity flip, complement rescue, threshold tuning,
checkpoint replacement, query-conditioned proposal, reroll, or denominator
change.

## Immediate safe work

Until an independent clean authority exists, useful work is limited to:

- unit/property tests over synthetic images and temporary stores;
- model-free replay of checked-in canonical records;
- source-bound verification of the observer, passed-fit, inference, custody,
  and calibration modules;
- object-bound cross-family witness and predicate design on synthetic or
  already exposed engineering fixtures;
- documentation and lifecycle cleanup; and
- retirement of remaining executors after their verification-only decoders
  and immutable preimages are secured.

No amount of additional testing turns this plan into launch authority. A
future launch must point to the new clean-cohort record, new preregistration,
new write-once stores, and every passed gate above.
