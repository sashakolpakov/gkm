\begin{abstract}
Bongard problems are underdetermined by their small support sets: a fluent
description, an accidental pixel separator, and the intended concept may all
fit the same twelve labelled panels.  The missing layer is therefore not a
theorem prover after prose, but an auditable connection from pixels to
observations.  We define a headless visual-semantic protocol over the complete
12,000-task ShapeBongard V2 release.  A support-only proposer may select from a
finite catalog of deterministic visual counts and may emit one affirmative
soft claim.  Candidate-independent Python extractors, a blind ordinal scorer,
a separately fitted development calibration, four-valued evidence, a
positive-only formula language, an exact support gate, and model-free replay
can turn that proposal into an operational predicate.  Soft prose remains a
model observation, not a proof about depicted objects.  Python alone defines predicate execution,
calibration, replay, benchmark decisions, and scientific artifact identity; a
proof assistant may only consume a frozen artifact as a detached optional
sidecar whose deletion changes no result, decision, or identifier.  The first
Stage-A experiment, A1, failed before scoring and produced no calibration or
accuracy estimate.  A distinct repaired-protocol experiment, A2, was
invalidated by a concurrent agent source edit after protocol/cohort freeze and
wrote no Stage-A terminal artifact.  Stage B is unauthorized by both A1 and A2.
Official test execution is disabled.  Thus this paper
specifies a benchmark protocol and its present representational gaps, not a
positive accuracy result.
\end{abstract}

\section{The theoretical hole}

A Bongard task supplies six positive and six negative support panels, followed
by one held-out panel from each side \cite{bongard1970pattern}.  Many rules can
separate twelve examples.  A proposed rule can exploit renderer artifacts,
generator-family regularities, a model's lexical habits, or extraction failure
instead of the intended visual concept.  Support accuracy alone does not say
which rule was learned.

The tempting account
\begin{equation}
  \text{panel}\longrightarrow\text{verbal description}
  \longrightarrow\text{formal predicate}\longrightarrow\text{proof}
  \label{eq:wrong}
\end{equation}
misplaces the hard problem.  A prover can check consequences of recorded
premises.  It cannot establish from syntax that ``bird-like object'' is a true
description of a PNG.  Formalizing the sentence only makes the unverified
perceptual premise look precise.

The implemented boundary is instead
\begin{equation}
\begin{aligned}
\text{exact panel bytes}
 &\longrightarrow \text{typed empirical observations}\nonumber\\
 &\longrightarrow \text{closed positive formula}
 \longrightarrow \text{support gate and replay}.
\end{aligned}
\label{eq:actual}
\end{equation}
The first arrow is empirical and must carry provenance, uncertainty, and a
declared failure state.  The later arrows are deterministic Python
computations.  Related visual-language and program-synthesis approaches also
make the representation boundary central \cite{depeweg2018solving,
sonwane2021using}; our contribution here is a narrower benchmark contract that
does not confuse replay with perceptual truth.

\section{Pinned corpus and exposure boundary}

ShapeBongard V2 contains 12,000 tasks and 168,000 panels
\cite{nie2020bongardlogo}.  The pinned release contains 3,600 Freeform
(\texttt{ff}), 4,000 Basic (\texttt{bd}), and 4,400 Abstract (\texttt{hd})
tasks.  Its primary split is 9,300 train, 900 validation, and 1,800 test tasks.
The extracted corpus manifest used by this protocol is

Each task and panel is also content-addressed.  Action programs, rule-bearing
paths, source filenames, family labels, and query labels remain verifier-side;
the proposer and scorer see staged neutral filenames and pixels only.

The released split and the local exposure ledger answer different questions.
The first supports comparison with the dataset.  The second prevents this
project from calling previously inspected tasks or semantic siblings unseen.
An append-only successor ledger is durably written before selected pixels or
model calls are released.  This controls the declared experiment, but it cannot
exclude foundation-model pretraining contamination in a public dataset.

\section{Executable visual semantics}

\subsection{One proposal, candidate-independent observations}

The proposer sees only the labelled support pixels and returns one typed
affirmative proposal: zero to three registered direct atoms and at most one
soft claim containing one to four positive cues.  It cannot return executable
code, feature weights, a threshold, a polarity bit, or a final Boolean.

Independently, each panel's exact PNG bytes are converted to a frozen visual
witness bundle.  The extractor receives no task identifier, side, label,
support/query role, proposed phrase, or formula.  It retains three fixed,
correlated preprocessing scenarios.  A complete conjunction is evaluated
inside each scenario before scenario outcomes are combined; coordinate-wise
feature intervals are not allowed to splice mutually inconsistent witnesses.

Every observation has exactly one disposition:
\begin{description}[leftmargin=3.1cm,style=nextline]
  \item[\texttt{present}] constructive evidence for the affirmative atom;
  \item[\texttt{certified\_absent}] an operational nonmatch under the frozen
    direct or calibrated contract;
  \item[\texttt{indeterminate}] scenarios disagree or an interval cannot
    decide the fixed boundary; or
  \item[\texttt{error}] extraction, transport, parsing, identity, or replay
    failed.
\end{description}
A failed fit or model call is never interpreted as evidence for the negative
class.  Indeterminate and error outcomes abstain and remain in the headline
denominator.

This catalog is intentionally modest.  It has no direct oblique-angle band or
typed corner-angle interval.  It has no two-loop point-contact predicate with
explicit loop owners, one contact witness, four owner-labelled incident rays,
and both exterior gaps.  It also lacks persistent object and part identity,
part correspondence, and open categories such as bird-likeness.  The crossing
count recognizes a geometric X in a thinned raster graph; it does not infer an
over/under crossing or identify four attached objects.  These are missing
perceptual legs, not alternate names for existing counts.

\subsection{Soft prose as an operational observation}

Open descriptions are still useful proposal language.  For example, a model
may propose ``bird-like object'' or ``mostly oblique parts.''  The fixed soft
path does not promote that text to a theorem:
\begin{enumerate}[leftmargin=1.5em]
  \item the support-only proposer freezes one affirmative claim and one to four
    affirmative cues;
  \item an isolated one-panel scorer sees the exact claim, cues, neutral
    \texttt{query.png}, and short verifier-produced witness summaries, but no
    task identity, side, role, or label;
  \item for every cue it returns \texttt{supported}, \texttt{ambiguous}, or
    \texttt{unsupported}; Python maps these to $1$, $1/2$, and $0$ and takes
    the fixed minimum across cues; and
  \item only if a valid scorer-family calibration has been fitted on
    development data does Python map the ordinal score to an interval and
    compare it with one fixed affirmative boundary.
\end{enumerate}
The artifact binds the text, cue inventory, panel digest, model and prompt,
raw receipt, ordinal map, aggregation rule, calibration bin, interval, and
evaluator.  A cited witness ID proves only that the response referred to an
offered witness; it does not prove bird-likeness.  Calibration estimates the
behavior of this operational scorer under a stated population and sampling
design.  It does not prove individual-panel semantics or transfer to another
family.

Whenever possible, development should replace a soft phrase with a direct
measurement.  ``Oblique'' should eventually bind specific corners or stroke
segments and return angle intervals in declared units.  ``Two loops touching''
needs object ownership and a complete contact signature.  This is the relevant
sense in which the predicate library can grow, analogous to reusable library
learning rather than task-local separator invention
\cite{ellis2020dreamcoder,bowers2023stitch}.

\section{Positive-only synthesis and reverse-alignment pathology}

The canonical Python IR contains positive atoms and their conjunction.  The
headless proposer has no \texttt{Not}, complement, disjunction, arbitrary
comparison, or dynamic function lookup.  Every selected atom is used once, and
the verifier assigns its identity.  A proposal must agree with all six positive
and all six negative support panels under fresh isolated evaluation.  The
formula and registry are then frozen before any query pixel is created in the
proposer's workspace.

The earlier PURE support diagnostic recorded 10 reversed outcomes among 132
executable support-panel outcomes.  It did not execute an A1 complement or
measure whether negation improved semantic accuracy.  The observation motivates
a concrete failure mode: if synthesis tries both
$p(x)$ and $\neg p(x)$ after seeing the labels, an incorrectly oriented or
spurious predicate can be rescued by its complement.  If an extractor failure
has first been collapsed to Boolean false, negation turns failure itself into
a positive witness.  With only twelve support panels, family correlations and
reused generator attributes make such accidental separators especially easy
to select.

The repaired protocol fixes the positive orientation at proposal time, has no
negation operation, distinguishes absence from failure, and rejects any rule
that misses the exact 12/12 support gate.  Query observations, joint
predictions, and labels occur only after the formula commitment.  Exact-byte
cold replay then reconstructs the deterministic computation without another
model call.  These restrictions prevent a \texttt{Not} rescue; they do not
make a poor visual vocabulary expressive or turn a support fit into evidence
of generalization.

\subsection{Stage B: conditional descriptive DEV run}

Neither the failed A1 receipt nor the invalidated A2 incident can authorize
Stage B.  The completed metadata-only audit shows why raw task count was
misleading.  Once semantic siblings and every HD constituent exposed by the
complete A2 ledger are removed, the remaining DRILL maximum is 24 BD plus zero
HD units, so the old 48-task calibration cannot be repeated.  DEV against the complete live ledger
has 16 BD and zero HD units.  The default 24-task request therefore fails before
pixels or model calls, while a 16-task BD-only pilot cannot meet the frozen
24-cluster minimum.  Any later run remains descriptive and records
\texttt{dependence\_design\_authorized = false}.

This strict capacity is not corpus exhaustion.  The train/validation split has
10,200 tasks, and 10,069 exact task identifiers remain absent from the complete
A2 ledger: 2,998 FF, 3,456 BD, and 3,615 HD.  An intermediate 28-unit upper
bound enforced HD constituent disjointness only within the proposed new batch;
the live 24-unit result also seeds exclusions from the predecessor ledger.  It
exposes a design conflation: scorer calibration and semantic-transfer
evaluation were forced through the same constituent-disjoint frame.  A future calibration
frame should use exact-unused training tasks with explicit shared-generator
dependence, score both held-out panels before label opening, and reserve a
separate evaluation frame.  HD evaluation must be partitioned by constituent
attribute rather than ordered pair.

New command receipts bind the complete executable Bongard Python source
boundary.  Source drift
after exposure now produces a durable typed failure with labels withheld.
Identity-preserving canonical caches reduced the same synthetic Stage-A replay
from 161.15 seconds to 11.50 seconds and Stage B from 218.88 seconds to
51.10 seconds.

Visual-semantic SEALED and official-test execution are hard-disabled in both
the CLI and direct benchmark runner.  Stage B has not run, and this manuscript
reports no Stage-B query score and no official-test accuracy.

\section{What formal verification can and cannot add}

Python is the sole authority for predicate construction and execution, type
checking, calibration, selection, persistence, cold replay, benchmark
decisions, and scientific artifact identities.  Canonical JSON is the
interchange representation.  A benchmark run does not require Lean or any
other proof assistant.

A future proof checker may consume a frozen artifact and independently check,
for example, that a conjunction follows from its recorded evidence.  It must be
a detached, removable sidecar:
\begin{itemize}[leftmargin=1.5em]
  \item no proof term enters a predicate or artifact identity;
  \item installation or deletion of the checker cannot change a result,
  benchmark or admission decision, digest, identifier, or replay;
  \item the checker cannot alter the canonical Python semantics; and
  \item a proof about recorded observations cannot certify the correctness of
  the original visual observation.
\end{itemize}
This ``un-Lean'' invariant keeps formal checking useful without making the
benchmark depend on a particular prover.  Stage-A source identity enforces the
boundary mechanically: it hashes every potentially authoritative Bongard
Python module but excludes the exact non-authoritative
\nolinkurl{bongard/semantic_checker.py} sidecar, so changing or removing that
adapter leaves receipt identities unchanged.

\section{Limitations and next work}

The protocol makes failures legible, but the central perception problem
remains.  The direct catalog lacks angle, contact, ownership, object identity,
and part-correspondence legs.  The soft scorer may be self-consistent yet
semantically wrong.  A model provider and public-data training history cannot
be reproduced by exact-byte symbolic replay.  One held-out panel per side gives
high task-level variance.  The post-A2 frame has no ledger-disjoint HD DEV unit,
so descriptive BD-only results must not be dressed as broad population
inference.

The immediate work is therefore to preserve both failed histories and run A3,
if at all, from frozen source with one fresh no-reroll seed and its exact
seed-ranked capacity.  Before that seed exists, A3 fixes eight clusters in each
of the two score bins.  At 90\% simultaneous confidence the Hoeffding radius is
0.480161, so eight is the smallest bin that can possibly decide against the
unchanged 0.5 boundary.  This is a weaker descriptive design, not an
authorization result.  Independently, add the missing typed observables and
redesign the larger calibration frame.  Only a future, separately justified
design can decide whether official test access is warranted.

\section{Conclusion}

The project does not need Lean to make a visual predicate executable.  It needs
an honest empirical measurement boundary.  Exact-byte candidate-independent
witnesses, conditionally calibrated operational soft observations, four dispositions,
positive-only synthesis, a 12/12 support gate, commitment before query release,
and Python cold replay provide such a boundary.  The earlier reversal
diagnostics explain why post-hoc complementation is dangerous; A1 did not
measure negation.  The positive-only language prevents that repair from
receiving benchmark credit.  These controls also expose the real missing work:
angles, point contact,
ownership, and stable object identity.  Until those legs improve and the
descriptive stages complete, the correct result is one terminal A1 failure and
one invalidated A2 incident with no terminal artifact---not a successful
Bongard benchmark.
