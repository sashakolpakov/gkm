Historical Abstraction-Emergence Control
=========================================

This retained control asks whether description-length accounting favors one
shared predicate macro when the same predefined conjunction is reused:

.. code-block:: text

   objective = task loss + lambda * (library complexity + rule complexity)

The primitive Boolean atoms are supplied by the experiment.  Historical
conditions compared duplicated inline rules, a shared macro, syntax that
repaid the definition at every use, and an oracle upper bound.  Repeated
structure could make the shared macro cheaper; single-use and no-sharing
controls did not.

Claim boundary
--------------

This is an accounting result, not a visual Bongard benchmark.  It does not
learn objects from pixels, calibrate an empirical observer, enforce modern
custody, or establish generalization.  It assumes the Boolean atoms whose
construction is the hard part of the active visual track.

The current Bongard design instead requires candidate-independent typed
observations, four-valued evidence, a deterministic support-consistent version
space, and either a typed semantic gap or a frozen positive Python predicate.
Python can verify the downstream computation; neither Python nor Lean can prove
that a visual premise is true merely because it was serialized.

The latest skeleton-graph line improved observer capacity, passed-fit
authentication, raw-inference custody, delayed-label calibration, and cold
replay.  Its calibration campaign nevertheless ended before execution because
the HD action-program authority was pre-exposed.  The resulting typed custody
GAP is not an empty semantic version space.  Macro reuse and MDL accounting
cannot repair that custody failure, just as they cannot repair a missing visual
witness.

The earlier loop, five-task, and panel-soft campaigns remain historical
representation evidence.  Their live soft/prompt implementations have been
retired rather than kept as alternate execution paths.  See
:doc:`the current authority and historical results <bongard>`.

The original implementation and earlier reports are preserved at the
annotated Git tag ``pre-bongard-complete-rewrite-20260805``.  They must not be
combined numerically with later engineering campaigns or treated as a current
benchmark.
